Game ingest, and the sanctuary for models from abandoned games

How a game or a model gets into Abbie's World today, what has to change to take in models from old and abandoned games, and which of those models we can lawfully keep. Status: drafted. Nothing in this document has been built yet beyond what section 2 says already exists.

The short version

  1. Two lanes already exist and must stay separate. The Game Oracle lane learns a game's identity (style, feel, structure) and keeps no assets. The asset lane takes models with a known licence and runs them to a low-poly GLB in R2. The sanctuary is a third entry into the asset lane, with a stricter gate.
  2. "Abandoned" does not mean free. A game nobody sells, supports or remembers is still under copyright in nearly every case, and no commercial video game is old enough to be in the public domain. The sanctuary cannot be built on abandonment. It has to be built on a licence, a public-domain status or a written permission.
  3. Rights are checked before extraction, not after. Every asset gets a rights record first. Anything without one stays as Oracle notes in our own words, exactly as today.
  4. The best first candidates are games whose creators already gave the art away: Yo Frankie! (CC BY), Warzone 2100 (GPL art), Lugaru HD and 0 A.D. (CC BY-SA). Quake and Overgrowth are the cautionary cases: their code is open, their art is not.
  5. The real preservation value is the record, not only the mesh. We keep the untouched original (hashed), the licence as it read on the day, every tool and setting used, and the low-poly result, so any asset can be rebuilt later.

I am not a lawyer and this is not legal advice. The parts that carry real risk (ShareAlike and GPL terms inside a commercial game, takedown handling, anything involving a rights holder's characters) should be read by a copyright lawyer before the sanctuary opens to the public.

1. How ingest works today

There is no single "game ingest" tool. There are three separate pipelines, plus the shared store they end in. Everything below was read from the repo and team memory on 2026-10-23.

Lane A · Game Oracle (ideas, never assets)

tools/steam-study/ reads Evan's Steam library through the Steam client he is already signed in to. steam_study.py profile APPID records public store metadata and an engine fingerprint from file names in the install folder, never file contents. The study notes (library_notes.py, free_notes.py, owned_notes.py, reference_notes.py, rendering_notes.py) are written in our own words and study_games.py turns them into docs/oracle/games/*.json: 402 files today, 389 profiles. Deeper identity records live in docs/oracle/identity/ (schema 1.1, 20 records, a style-versus-expression ledger). The Oracle site shows each game at /game?id=… and the consult director turns an idea into rules and factory requests.

Lane B · Licensed models (Printables, STL to GLB)

tools/stl-pilot/ took 10 CC0 or CC BY models from Printables plus a toy-car variant. Evan's Chrome downloads them one at a time. stl_pipeline.py runs headless Blender: import, repair (weld, normals, holes, dust shells), scale to real metres, decimate to a band (prop 200 to 1,500 triangles, furniture 1 to 4k, building 3 to 12k, vehicle 3 to 12k, creature 5 to 15k), Smart UV, bake normal and AO from the untouched high-poly, role-named materials, export a GLB with 512 px textures. Each run writes notes.json with per-stage timings. Each model carries provenance.json: model URL, author, licence name and URL, date retrieved, origin, sha256 of every source file, a licence screenshot and the source image. The source STLs stay on the PC and are git-ignored.

Lane C · Generated models (Midjourney, Meshy, Blender)

Midjourney concept art and turnarounds, then either our own recipe (build.py, Blender Python, parts-first, per tools/ranch-rebuild/MODELER.md and docs/MODELER_VISION.md) or Meshy for hero characters (tools/meshy-heroes/, GitHub workflow meshy-run.yml, secret MESHY_API_KEY, 2,000 credit cap, reached 2026-10-23). Meshy is the answer key we learn from, not the pipeline we own. Brief, prompts, Midjourney job ids, picks, revisions and scores are kept per asset.

Where every lane ends: the store and the game

  • Manifest and the /models desk. prototypes/ranch-atelier/dist/models/manifest.json lists each model with id, name, group, subject, style, ask, urls (ref, glb, render), an outline and good/off notes. The Printables set sits in the group "Free sources · Printables" (publish_models.py), so it never mixes with the game's own models.
  • R2. tools/model-store/sync.mjs uploads blobs keyed by content hash and publishes models/catalog.json, catalog-all.json and paths.json. As of 2026-10-22 R2 held 1,171 models and 30 reference images. The Postgres model_assets table was not filled then because the POSTGRES_URL secret was wrong; check whether that has been fixed.
  • Into the game. /model-store.mjs points three.js loaders at R2 for any stored path, with the bundled copy as fallback. The game reads material names as shading roles (Timber, Plank, Stone, Metal, Glass, Leaf and so on), so ingested models must be renamed to roles.

2. Reconciling the sanctuary with the identity rule

The identity canon says: we assimilate style, never expression, and never extract a game's meshes, textures or audio into the repo, R2 or prompts. The sanctuary is a deliberate exception, so the exception has to be narrow and written down.

Proposed wording (to add to GAME_IDENTITY.md, not yet edited)

Default stays the same: any game's assets stay out of the repo, R2 and prompts. The one exception is an asset with a rights record that passes the sanctuary licence gate. Such an asset moves from the identity ledger's "protected expression" column to a new "cleared" list that names the sanctuary record id. Everything without a passing record stays style-only. Cleared assets never become style references for other games' expression either: the licence covers that asset, not the game's look as a whole.

In practice: the Oracle keeps studying every game it is shown, the sanctuary ingests only the few assets whose rights are clear, and the two never share an input folder.

3. The legal side, straight

"Abandoned" is not a legal category. Copyright runs from the author's death or the publication date, not from the last patch. A studio that closed, a publisher that was bought, a game pulled from sale: the copyright still belongs to someone, often a company that bought the catalogue.
  • No commercial video game is in the public domain yet. US copyright for corporate works lasts 95 years from publication, so the earliest games run into the 2060s. Public domain in practice means the author dedicated the work (CC0), the work came from a government body that does not hold copyright, or the work was never eligible.
  • "Abandonware" sites are tolerated, not licensed. Free to download is not free to modify, redistribute or put in another game. The same goes for "freeware" releases: they let you play the game, not modify or redistribute it.
  • Open-sourcing the engine rarely frees the art. id Software released Quake's engine under the GPL, and the Quake Wiki still lists the original models, maps and textures as id Software's, "not available under a free license". Wolfire released Overgrowth's code under Apache 2.0 and said the assets would not be released for free. Always read the licence of the assets folder, not the repository.
  • Preservation law does not help us host. In October 2024 the US Copyright Office declined a new exemption that would have let libraries and archives share old games remotely (Video Game History Foundation statement). Even the institutions whose job this is cannot lean on a preservation exemption for public access, so a small studio should not.
  • Fair use is not a hosting policy. A low-poly redraw of a copyrighted model is a derivative work. A fair-use argument would be made after a complaint, case by case, and a kids' game that sells is a weak place to make it.
  • Extraction is its own risk. Breaking encryption or protection to read a game's files can trip the DMCA anti-circumvention rule (section 1201) and the game's terms of use, even when the asset would otherwise be fine. Only extract from files obtained from the rights holder's own open release, or from a copy where the format is plain.
  • Characters and names are separate rights. A licence on a mesh does not clear a trademark or a famous character. Mario-like and Sonic-like designs stay "inspired by" (as the project rules already say for brands).
  • Outside the US the rules differ (moral rights in the EU, different terms in the UK and Japan). The sanctuary will be viewed worldwide, so the gate should be the strictest common denominator.

5. Recommended sanctuary policy

Licence gate (nothing is extracted before it passes)

TierAcceptRule
Green · ingestCC0, public domain, CC BY, MIT, BSD, zlib, Apache 2.0 for art; a written grant that allows modification, redistribution and commercial useIngest, publish, may be used anywhere in the game. Credit line when the licence asks for it.
Amber · sanctuary onlyCC BY-SA, GPL art, grants limited in scope or timeIngest into the sanctuary gallery and keep the same licence on the result. Do not put in the shipped game bundle until a lawyer says what ShareAlike does to a world that contains it. Write the consequence into the record (share_alike: true).
Red · refuseNon-commercial (NC) or no-derivatives (ND) licences, no licence, "abandonware", "freeware", fan rips from a commercial game, anything extracted by breaking protection, other people's characters and trademarksNot ingested. The game may still be studied by the Oracle in our own words. Abbie's World takes payments after launch, so NC is incompatible by design.

Two more checks apply to every tier. PG only: old games are often violent or mature; the standing project rule (PG, no NSFW) applies, and anything that fails it is skipped even when the licence is perfect. No private data: check the file for names, paths, emails and credits that belong to private people before publishing.

Credit line

"{asset title}" from {game}, by {creator}. Licence: {licence name} ({licence url}).
Rebuilt in low poly for Abbie's World. {licence terms that apply to the remake, e.g. "Shared under CC BY-SA 3.0."}

The credit lives in the record, on the model's page in the sanctuary, in the game's credits screen, and (for a diegetic touch) on a plaque or card where the model appears in the world. Even licences that ask for no credit (CC0) get a line: it is the cheapest preservation we can do.

Takedown path

  1. A public page with a plain form and one email address (Evan to choose; shown on the page as selectable text). Anyone claiming rights can use it. No account needed.
  2. Hide first, ask later. A claim hides the asset from the gallery and the game within 72 hours. Hiding is reversible; a wrong yes is not.
  3. Review against the record: does the licence snapshot still say what we recorded? If the claimant is right, remove the live copies and the R2 blob, mark the record withdrawn and keep the record itself (minus the file) as the audit trail.
  4. If the claimant is wrong, reply with the record and keep it hidden until resolved. A lawyer handles anything that mentions a court.
  5. Register a DMCA designated agent with the US Copyright Office. It is cheap, it is what gives a US host the safe harbour for user uploads, and it matters most once players can add things.
  6. Re-verify the licence of every Amber asset yearly. Licences can be re-issued or withdrawn.

Only for assets that already passed the gate. The aim is the original data exactly as shipped, then a conversion. Conversion target and what to keep

  • Target: glTF 2.0 / GLB, Y up, metres, the same conventions as tools/model-challenge/MODELER.md (origin at footprint centre, front facing the agreed axis).
  • Conversion run: headless Blender (the same version the STL pilot uses, 4.1) with a fixed script per source format. The script, its arguments, the Blender version and the importer's name and version go into the record.
  • Textures: convert DDS, TGA, PCX, PVR to PNG with ImageMagick or Pillow. Keep the original files in the vault untouched.
  • Animation: keep the original rig and clips in the vault. Vertex-animation formats (MD2, MD3) are baked per frame into the vault copy; the game copy keeps only what we will use.
  • Never run a conversion on the only copy. Never edit the vault file. Never mix an asset from two games into one folder.

7. The preservation and provenance record

One JSON file per asset, extending the STL pilot's provenance.json (model URL, author, licence, date, hashes). It lives next to the model in the repo and is copied to R2 with it. Proposed schema name aw.sanctuary.record.v1.

  • Three kinds of copy, all hashed: the vault original (exactly as released), the working glTF (a direct conversion, no style change), and the game GLB (low-poly, role-named). A later technology change rebuilds the game copy from the working copy, per the modeler vision.
  • Where they live: repo for the small ones and all records; R2 under a sanctuary/ prefix for the vault and large blobs (same sha256 keying as the model store, so no second storage path). For a green-tier asset, also deposit the original and record in the Internet Archive as an off-site mirror; the licence allows it and it is the best insurance against our own site going away.
  • Change requests make a new version (the project rule). A restyle, a fix or a withdrawal is a new history event, never a silent overwrite.
  • Licence snapshot matters. Pages change. A PDF or screenshot of the licence page with its hash and capture date is the evidence if a claim comes in.

8. The ingest path into our low-poly style

find candidatelicence gateacquire + hash + snapshotvault originalconvert to glTFnormaliselow-poly passreviewpublish + credit
  1. Find. From the shortlist (section 9), an OpenGameArt-style filter on CC0/CC BY, or an Oracle record that notes "open assets". The Oracle can flag these: add rights_hint to a game's identity record. A hint is never the gate.
  2. Gate. Fill rights first. A second person (or a second pass by Claude, recorded as such) confirms the licence text against the assets, not the repo front page. Red stops here.
  3. Acquire. Download from the creator's own release. Hash the archive. Snapshot the licence. Nothing circumvented.
  4. Vault. Put the untouched originals under the sanctuary prefix.
  5. Convert. Format-specific script from section 6, into the working glTF. Check it opens in the viewer with orbit and zoom.
  6. Normalise. Reuse stl_pipeline.py stages: repair, scale to metres, pivot, orientation, material renaming to game roles. Add an origin-scale check: old games use arbitrary units, so confirm size against a real-world reference.
  7. Low-poly pass. Two modes, chosen per asset: (a) faithful, decimate to the band for its type, bake normal and AO from the original, keep proportions; (b) re-author, rebuild from the silhouette with a Blender recipe as in MODELER.md, using the original as the reference image. Mode (b) is what the STL pilot found necessary for thin or messy meshes. Budgets are the ones already in tools/ranch-rebuild/MODELER.md (chicken 1.5k, horse or cow 4k, building 9k).
  8. Style. The sanctuary shows the faithful conversion beside the game version, same camera, one link (existing rule: show every model beside its pick). The original look is preserved in the working glTF; the game version wears our look.
  9. Review. PG check, scale check, the credit line, the viewer. Score with the existing harness where it applies.
  10. Publish. Add the manifest entry in a new group "Sanctuary · {game}", commit the record, let the model-store Action sync to R2, preview through the instant-preview route, then the Ranch batch. Placement in a world follows the usual tour and design-card rules (tour: true or false on the whats-new entry).

Where Meshy fits: not at all for the sanctuary. Meshy and Midjourney make new things from a picture. The sanctuary preserves an existing thing. If we ever lack the source mesh but hold a clear licence on screenshots or concept art, that is a separate question for the Lane C rules.
